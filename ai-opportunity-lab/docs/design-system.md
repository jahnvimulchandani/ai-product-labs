# AI Opportunity Lab Design System

## Product Feel

Premium technical editorial. Calm, sharp, evidence-led.

Not playful. Not generic SaaS. Not fake AI.

## Colors

- Paper: `#FFFDF8`
- White: `#FFFFFF`
- Near Black: `#0B0D10`
- Graphite: `#1C2025`
- Butter Yellow: `#F3DE75` - signature cue / main highlight
- Pastel Sky: `#A9D9F0` - data, structure, architecture
- Spring Green: `#BCE8A6` - verified, safe, trust
- Turquoise: `#50C7C2` - live/system processing moments only

## Color Rules

- 88-92% neutral composition.
- Use one dominant Butter Yellow event per screen.
- Pastel colors encode meaning, not decoration.
- Use light mode first.
- Reading-heavy report screens must be light.
- Use dark mode only for hero or transition screens if needed.
- Do not place Sky and Turquoise directly beside each other; use Spring as the bridge or separate them spatially.
- Choose either a colored surface or colored text, not both from the same color family.

## Typography

- Headlines: General Sans, 600/650.
- Body: Manrope, 400/500.
- Metadata/data: IBM Plex Mono, 500.
- If fonts are unavailable, use clean system sans-serif fallbacks.
- Body copy should stay readable at 45-75 characters per line.
- Metadata can use small uppercase with tracking.

## Layout

- Strong negative space.
- Strict, left-aligned grid.
- Flat planes.
- 0-2px radius for editorial surfaces.
- 4-8px maximum radius only for functional product UI modules.
- Minimal borders only when structurally useful.
- Use 1px neutral hairlines for tables, axes, or true separation.
- No heavy shadows.
- No glassmorphism.
- No gradients.
- No decorative blobs.
- No fake AI graphics.
- No over-rounded SaaS cards.

## Required Demo Flow

1. Idea input
2. Clarifying MCQ cards
3. Audit loading
4. Final audit report

## Idea Input

Title:

> Audit an AI idea before you invest in it.

Subtext:

> Describe the opportunity. The system will extract what it can, ask only what changes the decision, then return a structured audit, roadmap, and tester flow.

CTA:

> Start audit

Sample buttons:

- Support reply drafting
- SOP Q&A assistant
- Competitor chatbot pressure
- Autonomous candidate rejection
- Churn risk investigation

## Clarification MCQ

- Show one question at a time.
- Show why the question matters.
- Show three suggested answers.
- Always show fourth option: Custom answer.
- Allow "I don't know yet."
- Never re-ask a confirmed field.
- Keep progress subtle.

## Final Report Sections

- Verdict
- Confidence
- Why this decision
- Architecture comparison
- Risk gates
- Unknowns and assumptions
- Roadmap
- Tester flow
- Scale path
- Metrics
- Evidence register
- Market context placeholder

## Copy Rules

Use precise product language.

Bad:

> Improve efficiency.

Good:

> Measure current handling time before claiming saved effort.

Bad:

> AI can automate everything.

Good:

> This can be tested as a controlled workflow with human approval.

## Portfolio Rule

The public portfolio should show the demo UI and case study. Do not add a "View GitHub repo" CTA.

## Usage Ratios

- Neutral: 88-92%.
- Butter: 4-6%.
- Sky: 2-4%.
- Spring: 1-3%.
- Turquoise: no more than 2%.

## Approved Pairings

- Butter + Sky for hero or key insight.
- Sky + Spring for structured comparison.
- Spring + Turquoise for verified-to-live progression.
- Butter + neutrals as the default signature combination.

## Data And Charts

- Neutral structure first.
- Use Sky, Spring, and Turquoise as semantic series.
- Do not use Butter as a chart series; reserve it for a heading or one key stat.
- Do not invent performance claims. Illustrative numbers must be labelled illustrative.

## Imagery

- Product artifacts first: screens, eval tables, decision outputs, and system states.
- Crop screenshots tightly with neutral framing.
- Remove private, employer, or client data.
- Every visual must communicate information.

## Icons

- Use 1.5px outline icons on a 20/24px optical grid.
- Use icons only when they encode meaning or aid operation.
- Avoid filled, duotone, sparkle, or decorative icon families.

## Motion

- Use one meaningful motion behavior per screen.
- Motion should explain progression or system state.
- Timing should be precise: 180-450ms for microinteractions, 600-900ms for narrative transitions.
- Avoid bouncy or cartoon easing.
